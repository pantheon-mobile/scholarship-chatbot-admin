# F-003・F-004：受信制限とフォーム解析の更新

## 変更

- FastAPI 0.141.1 / Starlette 1.7.0 に固定。F-004の3件の修正版を含む組合せ。
- ASGIミドルウェアで本文解析より前にContent-Lengthを確認し、受信中の実バイト数も制限する。ヘッダーがなくても制限が有効。
- 上限超過はHTTP 413と日本語メッセージを返す。multipart解析途中の一時ファイルも閉じる。
- TXT/CSVの文字コード検査は64KiBずつ読み込み、文字の途中で分割された場合も継続デコードする。

## 受信上限

- ファイル追加：501MiB（既存のファイル合計500MiB＋フォーム等の余裕）。既存の1ファイル100MiB・100件制限も継続。
- FAQ・データソース一覧・Webサイト一覧のExcel取込：11MiB（10MiB＋フォーム等の余裕）。FAQ・データソース一覧の既存10MiB検査も継続。
- その他のAPI：10MiB。
- Starletteのフォーム文字列フィールド上限は既定の1MiB。フォームの項目数制限もライブラリの既定値を使用。
- 多数の同時リクエストの合計使用量やExcel解凍後サイズは別課題。この変更だけで全DoS対策が完了するものではない。

## 自社開発環境の検証

自社のDeploy developmentワークフローで既存スモークテスト後に
`scripts/verify-upload-security.py` を実行する。
自社開発URLとの一致を確認し、共通パスワードはSecrets Managerから取得してログには出さない。
非公開FAQと回答利用無効の一意なファイルを登録し、Excel取込・チャット・受信制限・後片付けを確認する。
検証結果はGitHub Actionsのdevelopment-deploy-report成果物に保存する。
客先のデプロイワークフローは変更しない。本変更はまず自社リポジトリのみへプッシュする。
