# データソース更新仕様（2026-09-16 顧客確認済み）

## 状態と更新

| 状態 | 編集・トグル変更・同名ファイル／同一URLによる上書き |
| --- | --- |
| 利用可 | 更新を受け付け、準備中にする |
| 準備中 | 更新を受け付け、最新内容を処理待ちにする |
| 学習中 | 更新を拒否し、状態を維持する。処理完了後の再操作を案内 |
| エラー | 更新を拒否し、状態を維持する。削除後の再登録を案内 |

一覧ファイル取込では変更がある行のみ対象とする。変更のない行は状態にかかわらず更新・再処理しない。入力エラーや更新不可の行があれば取込全体を取り消す。

エラーの原因はファイル不備に限定しない。変換・外部サービス・通信等の失敗もあり得るが、今回の運用仕様では削除・再登録に統一する。

## カテゴリ・種別

- カテゴリの名称・親カテゴリの変更は、そのカテゴリと子孫カテゴリが設定されたデータを対象にする。
- カテゴリ削除は子孫を含む。対象データのカテゴリを未設定にする。
- 種別値の名称変更・削除は、その値が設定されたデータを対象にする。削除では関連付けを解除する。
- 対象に学習中・エラーが一件でもあれば、マスタ変更全体を拒否し、対象のID・タイトル・状態と再操作方法を表示する。
- 対象が利用可・準備中のみなら、マスタ変更と再処理予約を同じトランザクションで確定する。対象外データは更新しない。
- 種別ラベル名はメタデータに含まれず、ラベル名の変更は再処理しない。値の表示順だけの変更も対象外。
- 名称・親カテゴリに変化がない保存では再処理しない。

## 追加画面からの上書き

- 同じファイル名なら既存IDを維持し、ファイル本体と送信された登録情報を置換する。
- 同じURLなら既存IDを維持し、送信された登録情報を更新して再取得を予約する。
- 一致判定は正確な文字列一致。URL前後の空白は除去するが、末尾スラッシュ・クエリ・大文字小文字などを同一視する追加の正規化はしない。
- 別ファイル名・別URLでタイトルが同じでも登録できる。
- 旧実装で同名ファイル・同一URLが複数登録済みの場合は、上書き先を選ばず重複エラーにする。対象IDを表示する。
- 一度に同名ファイル・同一URLを複数指定した場合も拒否する。
- 複数ファイル追加、Webサイト一括追加／ファイル一括入力でエラーになった場合は、その操作全体を取り消す。
- ファイル置換は新しい保存キーに本体を保存し、DB確定後に旧ファイルを削除する。DB確定前の失敗では元のファイルを維持する。

## 反映タイミングと競合対策

準備中への変更だけでは学習側の情報は変わらない。定期バッチまたは「今すぐ実行」による処理完了で利用可になる。

管理メタデータの書き込みとワーカーのジョブ取得はPostgreSQLのトランザクション単位の共通ロックで順序を確定する。AI処理・変換中はこのロックを保持しない。編集が先に確定した場合、ワーカーは更新後の内容を取得する。学習開始が先なら編集を拒否する。

Web自動再取得の新規予約は利用可のデータのみ対象とし、エラー状態を自動的に準備中へ戻さない。
