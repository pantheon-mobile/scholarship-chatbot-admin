# チャットの会話文脈の引継ぎ

## 利用者向けの動作

1. 同じチャットの直前の質問・回答を踏まえ、「さっきの」「後者」「その条件」などを解釈する。FAQ回答も文脈に含む。
2. 過去のチャットを履歴から開くと、そのチャットの保存済み会話を使って続きを質問できる。ブラウザ再読み込み後も履歴から再開できる。
3. 「昨日相談した件」「以前聞いたこと」など別の会話を指す質問では、本人の直近30日・最大20チャットを候補にする。話題の確認への返答でも候補を引き継ぐ。今回の質問だけで話題が明確な場合には、別の会話の条件を勝手に追加しない。

別チャットの参照は設定ファイルで制御する。初期値はオン。画面に切り替えUIは設けない。オフでも現在開いているチャット内の会話は引き継ぐ。チャット履歴機能を環境設定で無効にした場合は、別チャット参照も無効。

別の会話を採用した回答には、参照したチャット名を表示する。これは資料の【参照元】リンクとは別。複数の候補から話題を特定できなければ、制度名等を確認する質問を返す。日付は日本時間で判断する。

## 環境ごとの設定

- 自社AWS：`infrastructure/config/development-ci.json` の `chatCrossSessionMemoryEnabled`。
- 客先AWS：`infrastructure/config/customer-validation.json` の `chatCrossSessionMemoryEnabled`。
- `true` で有効、`false` で無効。変更後は該当環境へ再デプロイする。
- ローカル：`.env` の `CHAT_CROSS_SESSION_MEMORY_ENABLED=true/false` を設定し、バックエンドコンテナを再作成する。
- 判定はサーバー側で行うため、ブラウザから有効化を指定することはできない。

## 処理の流れ

1. フロントエンドが現在の `chat_session_id` を送る。
2. サーバーが認証済みの `site:subject` から既存の履歴用識別子を計算し、チャットの所有者を照合する。他人のIDや削除済みIDは404。
3. 現在のチャットから完了済みの直近8往復を読む。質問は1件1500文字・回答は2500文字、合計16000文字まで。古い往復から除外する。
4. 別チャット参照が必要な場合は直近30日内の完了済み会話から、最新の質問日時順に最大20チャットを選ぶ。候補ごとに直近2往復、質問400文字・回答600文字までを渡す。同じチャットや、期間外・未来日時の会話は候補にしない。
5. Bedrock Converseで「単独の質問／文脈を補った質問／要確認」を構造化して判定する。既存の `CHAT_MODEL_ARN` を使用する。外部のツールを実行するものではなく、`resolve_question` の構造化出力だけを受け取る。
6. 補った質問を、FAQ照合・検索優先度の選定・資料検索と回答生成のすべてに使用する。現在の資料で回答を再確認する。

履歴の回答は指示語・話題の理解にのみ使う。過去のAI回答の金額・期限などを資料の代わりに信じて回答しないようモデルに指示する。指示語の解決はAIによる判断なので、完全な正解を保証するものではない。

過去の会話が見つからない・曖昧・文脈解決APIが失敗した場合には、制度名等を含めた再質問を求める。この確認応答は `GENERATED_AI`、参照資料なしとして扱う。

## 保存と削除

- 専用の長期メモリDB、履歴コピー、要約キャッシュは作らない。既存のチャット履歴を毎回読むため、DBのマイグレーションは不要。
- 利用者が削除したチャットは次回以降の候補から外れる。選択後にも存在と所有者を再確認する。
- 管理者であっても、文脈として使うのは本人の会話のみ。他の利用者の履歴を参照しない。
- ブラウザが渡す旧 `bedrock_session_id` は互換性のため入力として受け付けるが使用しない。回答生成も毎回新しいBedrockセッションで行い、削除済み・別利用者・古い会話の状態を引き継がない。
- 過去の会話を引用・説明した結果が別のチャット内にすでに保存されている場合、その別チャットの文章まで遡って削除する機能ではない。
- 別チャット名の表示は当該応答時のみ。追加した `context_reference` は既存の履歴データには保存しない。

## 制限・費用

- 現在の会話は直近8往復かつ文字数上限内。別チャットは直近30日・最大20件の候補の抜粋であり、全履歴を無制限に記憶する機能ではない。
- 候補に含まれない会話を再開したい場合は、該当チャットを履歴から開くか、制度名・条件を明示する。
- 参照の表現は日本語の「昨日」「以前」「前回」「さっき」等と一部英語を対象とする。あらゆる曖昧な表現を検出できるわけではない。
- 文脈を使う質問は、通常の資料検索・回答生成に加えてモデル呼出しが1回増える。履歴量に応じて待ち時間と利用料が増える。
- 既存の実行ロールにある `bedrock:InvokeModel` を使用。文脈解決でConverseのツール指定に対応するモデルが必要（現在の開発環境のClaude Sonnet 4.6で試験）。モデルを変更する場合は同じ試験を行う。

## 検証

- DBテスト：本人限定、他人のID拒否、削除済み・期間外除外、件数と文字数の上限、FAQを含む会話。
- APIテスト：補完した質問がFAQ・回答生成に使われること、クライアントのBedrockセッションIDを転送しないこと。
- UIテスト：FAQを挟んだ連続質問、履歴再開時の元ID、失敗した質問があっても次の連番が衝突しないこと、切り替えUIがないこと、参照したチャット名。
- 実モデルテスト：架空の会話のみを自社AWSのConverseへ渡し、同一会話・話題変更・昨日の会話・複数候補・履歴なし・履歴内の不正な指示の6ケースを確認。

通常のテストではAWSへ接続しない。実モデル試験は `RUN_BEDROCK_CONTEXT_TESTS=1` と適切なAWSプロファイル・`CHAT_MODEL_ARN` を明示したときだけ実行される。
