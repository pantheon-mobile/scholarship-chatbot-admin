- F-006：使用済みCPFトークンIDの保持期間を、有効期限に認証猶予時間を加えた時刻まで延長。

- F-011：Cookie認証の更新要求には許可済みOriginを必須とし、許可外Originを拒否。CPFのトークン交換はフロントの同一オリジンから行う。CORSとは別に実施。
- F-012：リハーサル環境名は `rehearsal-` で始まる専用名のみ。既存スタックへの上書きを拒否。自社mainでのみワークフロー実行可能。並行したリハーサル実行も防ぐ。実際のIAM権限範囲は別途確認。
- F-013：アプリDockerとCIのNode.jsを24系に更新。
- F-014/F-020：OIDCトークン発行権限をデプロイジョブに限定。CIの権限をreadに明示。手動デプロイもmainに限定。mainの自動デプロイは維持。GitHub側のブランチ保護・AWS信頼ポリシーは別途確認が必要。
- F-017：S3等の削除・KB同期待ち・ファイル保存・FAQ比較・履歴出力・URL一覧解析のブロッキング処理をスレッドへ移動。他のAPIのイベントループを直接停止させない。CPU・メモリ総量や並列数の制限は別途必要。
- F-018：URL一覧解析は既存100件制限の超過を読み込み途中で検出し、不要な追加データの読み込みを抑える。圧縮展開量の新規上限は未実装。
- F-021/F-022/F-023/F-029：全マスタ・履歴のExcel文字列は数式ではなく文字列セルとして保存。CSVの数式相当文字列は先頭にアポストロフィを付与。XMLに保存できない制御文字等を出力前に除去。改行・タブは保持。
- F-025/F-033：アクセス・質問等の日時はサーバー受付時刻を使用。IPは信頼するプロキシから受け取った場合のみX-Forwarded-Forを右から解析。最初の信頼対象外のIPで止める。アクセス記録のサイト区分は引き続き端末申告の参考情報であり、サーバーが実ページ閲覧を証明する監査記録ではない。この点は残課題。
- F-026：参照元URIをHTTP(S)と専用ダウンロード経路に限定し、API入力・履歴出力・画面描画で検証。旧履歴の危険なURIも画面にリンクとして出さない。
- F-027：回答本文・種別・FAQ ID・参照元・回答完了日時は `/chat/messages` が保存。ブラウザからのcompletionは保存済み回答との一致を確認するのみ。成功した回答を後続の通信失敗通知で消さない。過去の記録の真正性を遡って保証するものではない。
- F-028：開発環境でも内部例外を画面に返さずサーバーログに記録。
- F-036：Web取得の全接続（リダイレクト・robots.txtを含む）でDNS解決後の全IPを検証し、公開IPに限定。検証したIPに接続先を固定し、HTTPSの証明書検証・SNIには元のホスト名を使用。環境変数のHTTPプロキシは使用しない。学内専用サイトなど非公開IPへの取込は拒否する。

F-024・F-035は以前の修正を維持。F-035のS3/KBとDBの非原子的な失敗回復問題は、ロック順序の問題とは別。

## 設定と移行上の注意

### ローカルcompose

`.env` に以下を設定する。新規環境ではそれぞれ異なる十分長いランダム値を生成する（例：`python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`）。秘密値はコミットしない。

- `LOCAL_DB_PASSWORD`：DB用。既存DBボリュームを使う場合は現在のDBパスワードに合わせる。環境変数変更だけでは既存DBのパスワードは変わらない。
- `ANALYTICS_IDENTITY_SECRET`：既存環境では現在の値を維持する。安易に変更すると履歴の利用者識別が変わる。
- `CPF_DEVELOPMENT_JWT_SECRET`：開発用JWT署名鍵。疑似ログインの共通パスワードとは別物。

アプリをcompose外で起動する場合は `DATABASE_URL`、または `DB_HOST` と `DB_PASSWORD` を明示する。AWSでは従来どおりSecrets ManagerからDB認証情報が供給される。

### CSRFと接続元IP

- `CORS_ALLOWED_ORIGINS`：フロントエンドの正確なoriginをカンマ区切りで設定。`*` は使わない。スクリプトでCookie認証の更新APIを呼ぶ場合も正しい `Origin` ヘッダーを送る。
- `TRUSTED_PROXY_CIDRS`：プロキシとして信頼するIP範囲。未設定ならX-Forwarded-Forを無視する。CDKではVPCのCIDRを設定し、ECSへの入口をALBのSecurity Groupに限定する。新規ALBはappendモード（ポート付与なし）を明示する。既存ALBは実際の設定を確認する。既存ALBや別プロキシ経路がある場合は設定確認が必要。
- アプリ前段で勝手にIPを書き換えないよう、AWSのuvicornは `--no-proxy-headers` を指定。compose外の独自起動でも同様にする。

### 回答保存API

`/chat/messages` は認証済み利用者が所有する `chat_session_id` と `interaction_id` を必須とする。画面・検証スクリプトも同時更新する。古い画面を開いたままの場合は再読み込みが必要。
回答完了日時はサーバー保存時刻となる。既存の履歴・評価・削除仕様は変更しない。

### リハーサル

新規の `rehearsal-...` 名、HTTPS証明書ARN、対応する一時ドメインが必要。DNSは対象環境へ設定する。既存スタックは再利用しない。ワークフローの入力だけではDNSレコードを作成しない。
